# attrx — автоматическое заполнение характеристик товаров

Решение команды **10LVL** для кейса №3 хакатона «Точка сборки» (кейсодатель — **М.Видео**).

По тексту карточки (название, описание) и категории `attrx` заполняет характеристики из схемы категории. Для каждого значения возвращаются:
- **вероятность того, что значение верно**, откалиброванная на отложенной выборке;
- **статус**: `accept` (сразу в каталог), `review` (модератору) или `reject`;
- **подтверждение**: фрагмент текста карточки или ссылка на карточку-аналог в каталоге.

Значение без подтверждения не выдаётся никогда.

## Результат на отложенном тесте

Тест — `test_core`: 1 398 карточек из топ-30 категорий по трафику (60% кликов). Продавцы и 1P-бренды этих карточек не встречались при обучении. Подробности: [docs/DATA_CONTRACT.md](docs/DATA_CONTRACT.md), расчёт — `notebooks/03_hybrids.ipynb`.

| Конфигурация | Precision | Recall | **F1 с весом трафика** [95% ДИ] | Авто-заполнение | Точность авто | На проверку | ECE | мс/карточка |
|---|---|---|---|---|---|---|---|---|
| Baseline: словари и правила | 0.679 | 0.085 | 0.152 [0.147; 0.158] | 4.8% | 0.671 | 7.7% | 0.202 | 8 |
| + выученные шаблоны чисел | 0.691 | 0.096 | 0.171 [0.166; 0.178] | 5.4% | 0.695 | 8.5% | 0.181 | 9 |
| + аналоги из каталога (без верификатора) | 0.809 | 0.327 | 0.479 [0.462; 0.502] | 6.9% | 0.799 | 33.5% | 0.172 | 18 |
| + аналоги + верификатор | 0.839 | 0.387 | 0.540 [0.526; 0.558] | 5.4% | 0.970 | 40.7% | 0.016 | 19 |
| **+ похожие товары (основная)** | **0.830** | **0.484** | **0.630** [0.620; 0.642] | 5.0% | **0.974** | 53.4% | **0.010** | 30 |
| то же, аналоги публикуются без проверки | 0.830 | 0.484 | 0.630 | 19.7% | 0.944 | 38.6% | 0.010 | 31 |

Время — один поток CPU ноутбука (Python), без GPU и LLM. Доли — от эталонных полей.

Главное:
- F1 с весом трафика вырос в 4,1 раза по сравнению с baseline: без LLM, около 30 мс на карточку на CPU.
- Авто-публикуемые значения верны в 97,4% случаев. Гейт контракта — 95%. Порог выбран на val по OOF-вероятностям с перекрёстной калибровкой.
- Остальное уходит модератору: предложения на проверку покрывают 53% эталонных полей и верны в 82% случаев.
- Только 16–23% эталонных характеристик вообще упоминаются в тексте карточки. Поэтому главный рычаг полноты — аналоги и похожие товары из каталога, а не более сильная модель.
- Публиковать значения аналогов без проверки нельзя: точность авто падает до 0.944, ниже гейта. Поэтому этот режим выключен по умолчанию.

LLM-ступень (открытая Qwen3-8B, только для пропусков, с проверкой цитаты) считается в `notebooks/04_llm.ipynb`.
- На 172 карточках теста она поднимает долю найденных значений из текста с 70% до 76%. F1тр растёт 0.611 → 0.620; прирост не значим.
- Точность не падает: проверка отсеивает 65% предложенных LLM значений.
- Маршрутизация вдвое сокращает вызовы при 85% прироста.

Поэтому LLM — опция, а не основа. Подробности и стоимость — в [EXPERIMENTS.md](EXPERIMENTS.md).

## Быстрый старт

```bash
python -m venv .venv && .venv\Scripts\activate          # Linux: source .venv/bin/activate
pip install -e ".[data,dev]"                            # + ".[llm]" — шлюз, + ".[local-llm]" — своя GPU
set ATTRX_DATA_DIR=C:\hackathon_data                    # Linux: export ATTRX_DATA_DIR=...; внутри cu_ws/ из выдачи

python scripts/convert_skus.py %ATTRX_DATA_DIR%/cu_ws/skus.pkl %ATTRX_DATA_DIR%/processed   # каталог без pickle.load
python -m attrx build-data          # рабочий набор, групповое разбиение, схема категорий, индекс аналогов   (~1 мин)
python -m attrx train               # справочники, шаблоны, аналоги (train) + верификатор и порог (val)      (~3 мин)
python -m attrx run --sample test_core --out results/predictions.csv                                   # ~30 мс/карточка на CPU
python -m attrx evaluate --sample test_core --pred results/predictions.csv --report reports/metrics.md
python -m attrx serve --port 8000  # демо для модератора: http://localhost:8000 (pip install -e ".[demo]")
pytest -q
```

**Свои карточки.** `python -m attrx run --cards cards.jsonl` — поля `sku_id`, `category_id`, `title`, `description`; поддерживаются форматы parquet, csv и jsonl.

**LLM-режим:**
- `--llm` — OpenAI-совместимый шлюз хакатона, нужны `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `ATTRX_LLM_MODEL`;
- `--local-llm <путь к модели>` — своя GPU;
- `--max-llm-calls N` — дневной бюджет вызовов.

Ответы кэшируются по хэшу запроса, поэтому повторный запуск лимит не тратит.

**Судья (открытый аналог JEV, `notebooks/05_judge.ipynb`):**

```bash
pip install -e ".[judge]"
set HF_HOME=%ATTRX_DATA_DIR%\models\hf                    # или ATTRX_MODELS_DIR=<папка hub>
hf download convaiinnovations/laya-multilingual            # Apache-2.0, 1.2 ГБ
hf download ai-forever/FRIDA                               # MIT, 3.3 ГБ, для сравнения
# обучение судьи — ноутбук 05_judge (GPU 8 ГБ, ~20 мин для Laya); затем:
python -m attrx train --reuse-components   # переобучить верификаторы с признаками судьи, не пересобирая компоненты
python -m attrx run --sample test_core --config patterns+analogs+similar+judge
```

На машине без видеокарты ставьте CPU-сборку torch. CUDA-сборка torch 2.6 без доступной GPU не даёт transformers 5 создать модель (`Cannot access accelerator device`). Каскад без судьи от этого не зависит.

Артефакты в `work/artifacts`:
- `*.pkl` — pickle, загружайте только созданные своей командой `train`;
- судья хранится как `judge_<основа>.pt`, состояние модели без исполняемого кода (`weights_only=True`).

## Как это работает: каскад от дешёвого к дорогому

```
Карточка (title, description, category)
 │
 ├─ 1. Словари категории            бренды, значения из train-каталога, n-граммы токенов,       [lexicon.py]
 │                                   единицы и ё нормализованы, пары «Ключ: значение»
 ├─ 2. Выученные шаблоны чисел      «8/128Gb» → RAM/ROM, «42.5x72.2x6.3 см» → В/Ш/Г:             [patterns.py]
 │                                   какая позиция кортежа — какая характеристика, выучено на train
 ├─ 3. Аналоги из каталога          тот же товар у другого продавца (код модели + сходство        [analogs.py]
 │                                   названий); значение, только если аналоги согласны
 ├─ 4. Похожие товары               нет точного аналога → товары той же линейки (близкое          [analogs.py]
 │                                   название без кода); значение, только если ≥ 3 единодушны
 ├─ 5. Арбитраж                     согласие источников усиливает, противоречие ослабляет         [merge.py]
 ├─ 6. Верификатор (аналог JEV)     градиентный бустинг + изотоническая калибровка:               [verifier.py]
 │                                   P(значение верно | как и где найдено)
 ├─ 7. LLM для пропусков (опция)    только слоты без уверенного кандидата и только «текстовые»;   [llm_fill.py]
 │                                   маршрутизация по ожидаемой пользе; цитата ищется в карточке
 └─ 8. Статус                       accept: P ≥ порога val (точность ≥ 0.95) и есть подтверждение  [train.py]
                                     в тексте; review: P ≥ 0.5; иначе reject
```

**Каскад собирается из источников с одним интерфейсом** `candidates(title, description, category)` (`stack.py`). Новая модель или другой LLM-шлюз подключается без изменения остального кода.

**Схема категории выводится из данных.** В неё входят характеристики, заполненные у ≥ 50% train-карточек категории: 1 093 категории, медиана 15 полей. Ручной YAML для каждой категории не нужен.

## Честная оценка

Контракт данных и метрик написан до обучения: [docs/DATA_CONTRACT.md](docs/DATA_CONTRACT.md).

**Эталон и единица оценки:**
- эталон — характеристики каталога (`param *_search`) для 241 тыс. карточек, у которых есть текст;
- единица оценки — пара «карточка × характеристика схемы категории»;
- значения сравниваются после нормализации: единицы (1 ТБ = 1024 ГБ), ё, порядок частей.

**Групповое разбиение:**
- группа 3P-карточки — продавец, группа 1P-карточки — бренд;
- распределение 70/10/20 по `md5(group)`;
- случайное разбиение завышает F1 на 0.022 за счёт шаблонных описаний продавцов (`notebooks/02_baseline.ipynb`).

**Где что обучается:**
- справочники, шаблоны и индекс аналогов — только train;
- верификатор и пороги — только val (GroupKFold по продавцу);
- test используется только для оценки.

**Метрики:**
- precision и recall по всем эталонным парам;
- `recall_supported` — полнота на тех парах, где значение есть в тексте;
- F1 с весом трафика категорий (по кликам из `query_clicks`) с bootstrap-интервалом по карточкам;
- точность авто-публикации, ECE калибровки, мс на карточку, доля и стоимость LLM-вызовов.

## Соответствие требованиям кейса

| Требование кейса | Где реализовано |
|---|---|
| Вход — текстовая карточка товара | `cli_real.py: run --cards`, `catalog.py` (сборка из выдачи) |
| Заполнить характеристики категории | схема из данных: `catalog.py` → `schema.parquet`; каскад `stack.py` |
| Нормализация к каноническому виду | `values.py`: единицы, ё, многозначные значения, «1 ТБ» = «1024 ГБ»; значения из справочника категории |
| Уверенность для каждого значения | `verifier.py`: калиброванная вероятность, ECE 0.015 |
| Не выдумывать характеристики | evidence у каждого значения; LLM-значения проходят проверку цитаты (`llm_fill.py: _ground`); тесты `test_llm_fill_verifier.py` |
| LLM ограничена схемой и справочниками | `llm_fill.py`: только слоты схемы, примеры значений из справочника, только «текстовые» характеристики |
| Учёт стоимости, гибрид дешёвых и дорогих методов | каскад: LLM только для пропусков; кэш; бюджет `--max-llm-calls`; `run_stats.json` |
| Baseline → ML/LLM, вклад каждого шага | абляция: `notebooks/02_baseline.ipynb`, `03_hybrids.ipynb`, `04_llm.ipynb`; `EXPERIMENTS.md` |
| Петля обратной связи | статус `review` → модератор; подтверждённые значения пополняют train-каталог (справочники, аналоги, верификатор) при переобучении |
| Метрики P/R/F1, покрытие, вес трафика, срезы по категориям | `metrics.py`, `reports/metrics.md` (генерирует `python -m attrx evaluate`) |
| Одинаковое качество для всех категорий | срезы по категории, типу характеристики, 1P/3P в ноутбуках и `reports/metrics.md` |
| EDA с выводами | `notebooks/01_eda.ipynb` |
| Файл результатов | `results/predictions.csv` |
| Демо (порт 8000) | `python -m attrx serve` → `app.py`, `static/index.html`: значения, статусы, подсветка подтверждений, ссылки на аналоги |
| Продуктовая ценность | [docs/PRODUCT.md](docs/PRODUCT.md): сценарий, экономия времени модератора, метрики внедрения |

| 30069862 | 761 | Поддержка ГЛОНАСС | Да | | 0.99 | accept | flag | description | ГЛОНАСС |

## Риски и ограничения

| Риск | Мера |
|---|---|
| Галлюцинации LLM | LLM спрашиваем только о характеристиках, которые бывают в тексте. Цитата ищется в карточке, значение — в цитате. Не подтвердилось — значение отброшено и учтено в статистике |
| Значения от аналогов не подтверждены текстом карточки | Не публикуются автоматически: статус `review` и ссылка на аналог. Авто-публикация аналогов — отдельный флаг `--publish-analogs` (точность 0.970) |
| Новые бренды и модели без аналогов | Каскад деградирует до текста. На эти случаи нацелены LLM-ступень и пополнение справочников из очереди модерации |
| Эталон каталога неполон и местами расходится с текстом | Значение без эталона не штрафуется, а считается отдельно (`outside`). Метрика `recall_supported` отделяет потолок данных от ошибок модели |
| Сдвиг ассортимента | Схема, справочники и шаблоны пересобираются из каталога одной командой `build-data && train` |

## Структура

```
src/attrx/
  catalog.py      сборка набора, групповое разбиение, схема категорий, индекс аналогов
  values.py       токенизация и сравнение значений (единицы, ё, многозначные)
  lexicon.py      словари и правила, выученные на train (baseline)
  patterns.py     выученные шаблоны составных чисел
  analogs.py      аналоги из каталога
  merge.py        арбитраж кандидатов
  verifier.py     верификатор и калибровка (аналог JEV)
  judge.py        судья: «текст подтверждает / противоречит / не указано» на Laya или FRIDA, разметка из каталога
  configs.py      конфигурации каскада, основная конфигурация и политика статусов
  llm_fill.py     LLM для пропусков с проверкой цитат; local_llm.py — локальная модель с интерфейсом OpenAI
  stack.py        каскад источников; train.py — обучение и статусы; metrics.py — оценка
  cli_real.py     команды build-data / train / run / evaluate / serve; app.py + static/ — демо (FastAPI)
  title_model.py  отклонённый эксперимент (ML-извлекатель модели), см. EXPERIMENTS.md
  pipeline.py, schema.py, extractors/, evaluate.py, bench.py — офлайн-пример без данных (configs/, data/sample/)
scripts/convert_skus.py   потоковая конвертация skus.pkl без pickle.load (безопасность и память)
notebooks/                исследование, исполненные ноутбуки
docs/DATA_CONTRACT.md     контракт данных, метрик и гейтов
reports/                  метрики и бенчмарки (генерируются кодом), figures/ — графики
results/                  предсказания и статистика запуска
tests/                    pytest
```
