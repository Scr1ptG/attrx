# Контракт данных, метрик и критериев продвижения

Документ фиксирует, **что именно мы предсказываем, на чём учимся и как честно меряем**. Он написан до обучения моделей. Любое изменение метрики или разбиения вносится сюда отдельным коммитом с причиной.

## 1. Iteration Compact (итерация 1: baseline на реальных данных)

| Поле | Значение |
|---|---|
| Цель | По тексту карточки (название + описание) и категории заполнить характеристики из схемы категории. У каждого значения есть подтверждение: фрагмент текста карточки или карточка-аналог из каталога (см. раздел 2а) |
| Кому важно | Модераторы и контент-команда М.Видео (меньше ручного ввода), продавцы маркетплейса (быстрее публикация), покупатели (фильтры и поиск находят товар) |
| Владелец решения | Модератор: подтверждает поля со статусом `review`, поля `accept` публикуются автоматически |
| Что меняет модель | Предзаполняет карточку. Уверенные значения публикуются, сомнительные идут на проверку, пустые остаются продавцу |
| Главная метрика | Точность (precision) заполненных полей при пороге авто-публикации, взвешенная по трафику категорий |
| Ограничители | Полнота по подтверждаемым текстом атрибутам, покрытие полей, доля вызовов LLM и стоимость на 1 000 карточек, ECE калибровки, время на карточку |
| Бюджет ошибок | Не больше 5% неверных значений среди авто-опубликованных (precision@accept ≥ 0.95) |
| Недопустимые ошибки | Значение без подтверждения в тексте (галлюцинация). Неверный бренд. Неверные память, диагональ или объём у топовых категорий: из-за них товар попадает не в тот фильтр |
| Допустимые ошибки | Пропуск (поле остаётся пустым или уходит модератору). Значение, отличающееся от эталона только формой записи |
| Допущения | Эталон — характеристики из каталога (`param *_search`). Категорию продавец выбирает при загрузке, значит, она известна. Справочник брендов существует в продакшене |
| Ограничения | Только открытые модели и выданный LLM-ключ. Локально GPU 8 ГБ (RTX 4060), ВМ кейса — уточняется. Офлайн-режим без LLM обязателен |
| Данные | Срез от 14.10.2026: 241 355 карточек (каталог ∩ описания), 5,75 млн эталонных значений, 9 185 названий характеристик, 2 558 категорий |
| Baseline | Словари и правила, выученные на train: бренды, значения по категориям, числа с единицами, пары «ключ: значение» из описания |
| Кандидаты сигналов | Близость значения к названию характеристики. Блоки «• Ключ: значение». Единицы измерения. Эмбеддинги FRIDA. Извлекающая модель на GPU. LLM для пропусков |
| План порогов | Перебор порога уверенности на val: выбираем минимальный порог, при котором precision@accept ≥ 0.95 |
| Срезы оценки | Категория (топ-30 по трафику и хвост), тип характеристики (число, перечисление, да/нет, текст), продавец (1P «М.Видео» и 3P), источник подтверждения (название, описание) |
| Известные риски | Шаблонные описания одного продавца (утечка при случайном разбиении). Перекос в сторону штор и матрасов. Эталон местами расходится с текстом |
| Следующий эксперимент | Извлекающая модель (атрибут + текст → фрагмент) на слабой разметке, затем каскад с LLM только для пропусков |
| Откат | Офлайн-конфигурация `baseline` без моделей и без LLM всегда доступна и проверяется тестами |

## 2. Контракт данных

**Сущность и ключ.** Одна карточка товара — один `sku_id`. Это `offer_id` из каталога, который совпадает с `sku_id` в `sku_desc`. Дубли по `sku_id` отсутствуют.

**Вход модели (доступен в момент предсказания):**

| Поле | Источник | Обязательность |
|---|---|---|
| `title` | `sku_desc.title` | обязательно, null = 0 |
| `description` | `sku_desc.description` | может быть пустым |
| `category_id` | `offers.category_id` | обязательно (выбирается при загрузке карточки) |

**Эталон (только для обучения и оценки, во вход модели не подаётся):**
- `params` с суффиксом `_search`: точное значение (`value`) и единица (`unit`). Пары без суффикса — корзины фильтров, их не используем.
- «Бренд» = `offers.vendor`.

**Не используются как признаки:**
- `vendor`, `model` и `name` из YML: в продакшене их заполняет продавец, это частично и есть наша цель.
- Продавец: используется только для разбиения и срезов.
- Цена и клики: используются только для весов категорий.

**Служебные характеристики исключены из схемы.** Они не описывают товар и не выводятся из текста: «Гарантия предоставляется», «Вид выпуска товара», «Признак 18+», «Потратить бонусы», «Продавец», «Подборки», «Состояние», «Внешний вид».

**Схема категории (выводится из train).** В неё входят характеристики, заполненные хотя бы у 50% train-карточек категории, при наличии не менее 20 train-карточек в категории. Плюс «Бренд» для всех категорий. Тип характеристики определяется по значениям:

| Тип | Правило | Пример |
|---|---|---|
| `bool` | > 90% значений «Да» или «Нет» | Эффект памяти |
| `num` | > 90% значений — число | Ширина, см |
| `enum` | не больше 300 различных значений | Материал чехла |
| `text` | всё остальное | Цвет, Серия, Модель |

**Подтверждаемость.** Пара «карточка × характеристика» считается подтверждаемой текстом, если нормализованное эталонное значение найдено в названии или описании. Для чисел — то же число с допустимой единицей. Для `bool = Да` — упоминание названия характеристики. `bool = Нет` подтвердить текстом нельзя.

Важно: этот критерий сам по себе является правилом сопоставления. Поэтому полнота на подтверждаемом подмножестве немного завышена для правил. Главной метрикой остаётся полнота по всем эталонным парам.

## 2а. Происхождение значений (добавлено в итерации 2)

| Источник | Подтверждение | Может получить `accept` |
|---|---|---|
| Текст карточки: словари, шаблоны, правила, LLM | поле (`title` / `description`) и фрагмент. Для LLM дополнительно проверяется, что цитата есть в карточке, а значение — в цитате | да, при вероятности ≥ порога val |
| Аналог из каталога (train-часть) | `analog:<sku>` и название аналога | нет, только `review`. Флаг `--publish-analogs` меняет политику (решение бизнеса) |
| Похожие товары (train-часть, итерация 3) | `similar:<sku>` и название самого близкого товара. Значение берётся, только если ≥ 3 похожих товара единодушны (согласие ≥ 0.8) | нет, только `review` |

Гейт «галлюцинации = 0» означает: нет значения без подтверждения. Значения аналога и похожих товаров подтверждены каталогом, а не текстом, поэтому по умолчанию они не публикуются без модератора.

## 3. Разбиение и утечки

**Риск.** Один продавец публикует тысячи карточек по одному шаблону: у ООО «ВЕРТЕКС» 48 тыс. штор, у которых различается только принт. При случайном разбиении словари и модели запоминают шаблон, и качество выглядит лучше, чем будет на новом продавце.

**Политика: групповое разбиение.**
- Группа 3P-карточки — продавец.
- Группа 1P-карточки («М.Видео», 23% данных) — бренд: тексты пишет одна команда, а новое поступление в продакшене — это новые модели брендов.
- Группа попадает в train / val / test по `md5(group) mod 100`: 0–69 → train, 70–79 → val, 80–99 → test. Разбиение детерминировано и не зависит от версии библиотек.

**Контрольный замер.** Для сравнения считаем и случайное разбиение. Разница между ним и групповым показывает размер утечки шаблонов.

**Ограничение доминирования.** В оценочных выборках берём не больше 200 карточек от одной группы в одной категории.

**Аналоги и похожие товары.** Индекс строится только из train-групп каталога, включая товары без описания. Для test-карточки аналог или похожий товар — это товар другого продавца или бренда. Так устроен и продакшен: новая карточка сопоставляется с уже заведёнными.

**Что не допускается:**
- справочники, словари и пороги, построенные на val или test;
- подбор промптов на test;
- использование `vendor`, `model` или `name` из YML как входа.

## 4. Метрики

**Единица оценки** — пара «карточка × характеристика из схемы категории». Значение верно, если совпадает с эталоном после нормализации:
- регистр, буква ё, пробелы и пунктуация по краям не учитываются;
- числа сравниваются с переводом единиц: мм/см/м, г/кг, мл/л, Вт/кВт;
- многозначные значения («алюминий / пластик») сравниваются как множества.

**Подсчёт исходов (slot filling):**

| Исход | Как считается |
|---|---|
| Верное значение | TP |
| Неверное значение | FP и FN одновременно |
| Пропуск при наличии эталона | FN |
| Значение при отсутствии эталона | не штрафуется: схема каталога неполна. Учитывается отдельно как «вне эталона» |

**Метрики:**

| Метрика | Что показывает |
|---|---|
| `precision`, `recall`, `f1` (micro) | качество по всем парам |
| `recall_supported` | полнота на подтверждаемых текстом парах |
| `precision@accept` | точность только среди авто-публикуемых значений |
| `coverage` | доля пар схемы, где выдано значение |
| `traffic_weighted_f1` | F1 по категориям, взвешенный по доле кликов категории в `query_clicks` |
| `ece` | ошибка калибровки уверенности (10 корзин) |
| `llm_share`, `cost_per_1k`, `ms_per_card` | доля вызовов LLM, стоимость на 1 000 карточек, время на карточку |

Все метрики считаются и по срезам: категория, тип характеристики, 1P/3P, источник подтверждения.

## 5. Выборки оценки

| Выборка | Состав | Для чего |
|---|---|---|
| `val` | группы 70–79 | подбор порогов и конфигураций |
| `test_core` | test, топ-30 категорий по трафику (≈ 60% кликов), до 60 карточек на категорию | все конфигурации, включая LLM |
| `test_full` | весь test с ограничением 200 карточек на группу и категорию | только быстрые конфигурации без LLM |

## 6. Критерии продвижения (гейты)

Конфигурация заменяет текущую, только если на `test_core` выполняются все условия:

| Гейт | Порог |
|---|---|
| `precision@accept` | ≥ 0.95 |
| `traffic_weighted_f1` | выше текущей конфигурации, доверительный интервал bootstrap не пересекает 0 |
| Галлюцинации (значение без подтверждения в тексте) | = 0, гарантируется кодом |
| `ece` | ≤ 0.10 |
| `llm_share` | ≤ 0.30 |
| `ms_per_card` без LLM | ≤ 50 |
| Регрессия на срезах | падение F1 ≤ 0.02 на любом срезе топ-10 категорий |

Если конфигурация не проходит гейты, она остаётся экспериментом в `EXPERIMENTS.md` с объяснением, почему не принята.

**Дополнительно для источника, который даёт право на авто-публикацию значениям без собственного текстового подтверждения** (судья, `notebooks/05_judge.ipynb`):
- точность авто-публикации этих значений отдельно: нижняя граница Вильсона ≥ 0.95 на `test_core`. Свой порог `accept` выбирается на val только по ним — общий порог не должен прятать менее точный источник;
- выигрыш доказывается парным бутстрепом по карточкам: доля верно заполненных автоматически полей, нижняя граница Δ > 0;
- вето для LLM включается, только если на val среди отклонённых значений ≥ 70% неверных, а ложных вето ≤ 5% верных.
